# Bothy conformance vectors

Test vectors for format version 1 (`bothy_format = 1`). An implementation in any language can use
them to check that it reads and writes the same bytes and merges to the same state as the Rust
reference implementation.

The files are generated by `crates/bothy-conformance` and checked in CI:

```sh
cargo run -p bothy-conformance -- generate spec/vectors   # rewrite
cargo run -p bothy-conformance -- check spec/vectors      # verify
```

Fixed ids are used throughout: database `000102030405060708090a0b0c0d0e0f`, devices `a1…a1`,
`b2…b2` and `c3…c3` (16 repeated bytes each).

## Typed JSON

JSON can't tell `1` from `1.0` or represent bytes, so values use a tagged form:

| Value | Typed JSON |
|---|---|
| null, bool, text, array | `null`, `true`/`false`, `"text"`, `[...]` |
| int | `{"int": "-5"}` (decimal string, full 64-bit range) |
| float | `{"float": 1.5, "bits": "3ff8000000000000"}`. `bits` is the IEEE 754 binary64 value in hex and is authoritative |
| bytes | `{"bytes": "00ff"}` (lowercase hex) |
| map | `{"map": {"key": ...}}` |

- **Ops:** `{"hlc": "<16 hex>", "collection", "doc_id", "kind": "set" | "unset" | "delete", "fields"}`. For `set`, `fields` is an object of typed values. For `unset`, it is an array of names. `delete` has no `fields`.
- **Stamps:** `{"hlc": "<16 hex>", "device": "<32 hex>"}`.
- **State entries:** `{"collection", "doc_id", "deleted_at": stamp | null, "fields": [{"name", "stamp", "value"?}]}`. A field without `value` is unset.

Binary data (`cbor`, `bytes`, `dump`) is lowercase hex. Expected errors are `"corrupt"`,
`"format_too_new"`, `"key_required"` (an encrypted file read without the data key) or
`"wrong_password"`.

## Files

| File | What to check |
|---|---|
| `hlc.json` | `parts`: physical and logical parts ↔ u64 ↔ hex. `clock`: start a clock at `start` with `max_drift_ms`, run each step (`now` with a wall time, or `observe` a remote HLC at `wall`), and compare with `expect` |
| `values.json` | `valid`: decoding `cbor` gives `value`, and encoding `value` gives `cbor`. `invalid`: decoding fails with `error` |
| `ops.json` | Same as `values.json`, for single ops |
| `manifest.json` | `valid` manifests parse (the key's db id must match). `invalid` ones fail with `error` |
| `merge/*.json` | Apply `ops` (each with its device) to an empty state, in the listed order and in reverse. Both must give `state` and the canonical dump `dump` |
| `segment/*.json` | Decoding `bytes`, with the expected `db_id`, `device_id` and `seq`, gives `ops`. If `compressed` is false, encoding `ops` must give `bytes` exactly. `invalid.json`: decoding fails with `error` |
| `snapshot/*.json` | Reading `bytes` with the expected `header` gives `entries` and the version vector. If `compressed` is false, writing the entries with chunks of about `chunk_target` plain bytes must give `bytes`. `invalid.json`: reading fails with `error` |

| `crypto.json` | Argon2id (v0x13, 32-byte output): each `kdf` case gives `kek`. `key_check` verifies under `dek` with `aad` = db id bytes. The key file unwraps to `dek` with its password (`aad` = `"bothy-dek-v1"` ‖ db id ‖ key file key) and gives a wrong-password error for `wrong_password`. `sealed_json` opens to `plaintext` with `aad` = its key |
| `encrypted/segment.json` | XChaCha20-Poly1305 segments (`aad` = 96-byte header): decoding with `key` gives `ops`; uncompressed ones re-encode exactly with the given `nonce`. `invalid` cases fail with `error` |
| `encrypted/snapshot.json` | An encrypted snapshot (`aad` = header ‖ u32 BE chunk index) with fixed chunk `nonces`: reading gives `entries`, writing gives `bytes` |

zstd output differs between libraries and versions. For compressed files, only decoding is
normative. Sealed values are `nonce ‖ ciphertext ‖ tag`.
