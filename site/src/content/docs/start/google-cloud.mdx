Bothy has no server, so it signs in to Google Drive through an OAuth client of a Google Cloud
project.

**You can skip this page** if you use the prebuilt CLI or the Python package, and don't mind
the shared quota below. They include the clients of Bothy's own project, so `bothy auth login`
and `bothy.auth.device_login()` work with no setup.

**You need a project of your own** when:

- you build an app: Google shows your app's name at sign-in, and you get your own
  [quota](/concepts/limits/#google-drive-quota). Bothy's official clients are for Bothy's own
  tools, so Flutter apps always bring their own;
- you use a CLI built with `cargo install`, which has no official client;
- you run a fleet of devices, and don't want to depend on a quota shared with everyone else.

Creating one takes about ten minutes, once, and costs nothing. The command-line tool walks you
through it:

```sh
bothy setup google
```

It opens each console page below for your project and checks every downloaded client file:
right type, right project. Then it signs in and confirms that Google Drive answers; if the
Drive API is not enabled, it says so and links to the page. On other machines, run
`bothy setup google --project <id> --client <the same file>`.

The same steps by hand:

<Aside type="caution" title="One project per database">
Google Drive shows a project only the files that **that project's** clients created. Every
device of one database, whether the CLI, your Flutter app or a robot, must use clients of the
**same** Cloud project. So a database created through Bothy's official client can't be opened
through a project of your own, or the other way around. Choose before you store data.
</Aside>

<Steps>

1. **Create a project.** Open the [Google Cloud console](https://console.cloud.google.com/projectcreate),
   name it (for example `my-notes-sync`) and create it.

2. **Enable the Google Drive API.** In the project, open
   [APIs & Services → Library → Google Drive API](https://console.cloud.google.com/apis/library/drive.googleapis.com)
   and click **Enable**.

3. **Configure the consent screen.** Open **Google Auth Platform** (the OAuth consent screen):
   - user type **External**;
   - app name and your email;
   - under **Audience → Test users**, add the Google accounts that will sign in.

4. **Add the scopes.** Under **Data access**, add:
   - `https://www.googleapis.com/auth/drive.appdata`: the hidden per-app folder;
   - `https://www.googleapis.com/auth/drive.file`: a visible `Bothy/<name>` folder, needed for
     headless devices.

   Both are non-sensitive, so Google does not review them.

5. **Create the clients.** Under **Clients → Create client**, create what you need and download
   each JSON file:

   | Client type | Used by | Settings |
   |---|---|---|
   | Desktop app | CLI, macOS, Linux and Windows apps | none |
   | TVs and Limited Input devices | headless boards (device code sign-in) | none |
   | Android | Android apps | package name and the SHA-1 of the signing key |
   | Web application | Android apps (as the "server client id") | no redirect URIs |
   | iOS | iOS apps | bundle id |

6. **Hand the clients to Bothy.** For the CLI:

   ```sh
   bothy auth setup --client ~/Downloads/client_secret_desktop.json
   bothy auth setup --device-client ~/Downloads/client_secret_tv.json   # optional
   bothy auth login
   ```

   `bothy auth status` shows which clients are in use, and `bothy auth setup --official` goes
   back to Bothy's. For apps, see the [Flutter guide](/guides/flutter/) and the
   [Python guide](/guides/python/).

</Steps>

## Things that go wrong

- **"Access blocked" or "not a test user":** add the account under **Audience → Test users**.
- **`accessNotConfigured` or "Google Drive API has not been used in project…":** the Drive API
  is not enabled for the project of this client (step 2).
- **Signed out after a week:** while the consent screen is in **Testing**, Google expires
  sign-ins after 7 days. Sign in again, or publish the app (**In production**). An unverified
  app shows a warning screen at sign-in, which is fine for your own project.
- **The other device sees nothing:** check that both use clients of the same project, and that
  both chose the same [remote](/concepts/remotes/) (`appdata` or the same `folder:<name>`).
- **A headless board cannot join:** Google refuses the `drive.appdata` scope in the device code
  flow, so headless devices can only use **folder** databases. Create the database with
  `--remote folder:<name>` if a board will ever join it.
